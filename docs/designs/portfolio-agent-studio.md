## Problem Statement
Marlon's site is a two-page profile (home + about) that reads like a CV. He wants it to become the anchor for his future products: a place that shows his work and presents the AI automation studio he is starting, so that a small B2B founder can understand what he does and start a conversation.

## Demand Evidence
None yet, stated honestly. Nobody has asked Marlon for proof of work beyond the CV, and he cannot yet name a founder who has the problem today. The site is being built ahead of demand, so it must be cheap to build and must include an outreach step that creates the first asks.

## Status Quo
Marlon's own framing of the product: "improving productivity and integration made easy with client". Restated in this session as: done-for-you work that gets a client's or partner's data, specs and systems wired in, kickoff to go-live, without weeks of spec back-and-forth and manual re-keying. Today a small founder handles this with their own time, a contractor, or spreadsheets and chat groups. The cost has not been measured with a real founder yet.

## Target User & Narrowest Wedge
- **Primary reader:** a small Indonesian B2B founder with no integration team, who wants the integration done for them rather than a tool. Hiring managers stay a secondary reader, served by Home and About as today.
- **Narrowest wedge:** one done-for-you engagement, such as a single client or partner integration, scoped from first spec to go-live. Software products come later, built from what repeats across engagements.

## Constraints
- Stack is fixed: Astro static output, plain CSS in `src/styles/global.css`, no client-side JS, npm, Vercel.
- Design is the approved Console Bento system. New pages reuse its tiles, tokens and typography. No new fonts, no images over 100KB.
- All copy comes from `content/`, written by Marlon. Claude does not invent bio facts, services or prices.
- Day-job work stays sanitised: no employer name, partner names, internal system names, or numbers that cannot be defended.
- Any edit touching more than two files needs a three-line plan and Marlon's go-ahead first (CLAUDE.md rule). This build touches more than two, so implementation starts with that plan.

## Premises
Agreed in session, with two additions from Marlon:
1. The site's main reader is a small Indonesian B2B founder who needs an integration done for them. Hiring managers are second.
2. The first offer is a done-for-you service using Marlon's AI tooling, not a self-serve software product.
3. With no external clients yet, the proof is the agents Marlon has built plus the existing sanitised case study, not a gallery of past client projects. A worked sample of the method (a teardown of an invented partner spec) is a strong later item, listed under Open Questions, not part of this build.
4. Day-job work stays sanitised.
5. Site work stays small. Finding three real founders matters more than more pages.
6. Stack and Console Bento stay. The home spec's "no project grid, no blog" non-goals get revised for the new pages, not dropped.
7. **Added:** a Portfolio ("my work") page.
8. **Added:** an Agent Studio page, which is a company profile describing what the studio does. It is static and has no live tools.

## Approaches Considered
- **A, Minimal (rejected):** two hand-written pages. Fastest, but each new item needs a hand edit. The collection costs little more at two items and removes that edit from every later item, which matters for a site meant to grow with future products. Grouping by problem is deferred (see below), so B does not build ahead of content.
- **C, Studio-first home (rejected):** Studio replaces the home page. Rejected because it removes the profile-first home approved on 2026-09-19 that hiring managers rely on.

## Recommended Approach
**B, content-driven Work section plus a Studio profile page.** Chosen by Marlon on 2026-10-27.

### Routes
| Route | Purpose | Copy source |
|---|---|---|
| `/` | Unchanged hero, stats, Selected work, Now, Contact, plus one Studio tile. | `content/positioning.md`, `content/now.md`, the featured work item, `## Tile` in `content/studio.md` |
| `/work` | Portfolio index: a flat list of work items. | `content/work-index.md` for `<title>`, meta, h1 and intro; tiles from `content/work/*.md` |
| `/work/[slug]` | One page per work item. | one file in `content/work/` |
| `/studio` | Agent Studio company profile. | `content/studio.md`; contact links from `## Links` in `content/positioning.md` |
| `/about` | Unchanged. | `content/about.md` |

Nav becomes: `~/Marlon`, Work, Studio, About. The Studio nav item appears only when `/studio` is built (see Launch gating).

### Work items: one markdown file each
- Folder `content/work/`, loaded with an Astro content collection (`src/content.config.ts`, `glob` loader on `content/work`), so copy stays in `content/`.
- **Slug** is the filename. The existing case study is renamed to `content/work/claims-api-integration.md`, so its URL is `/work/claims-api-integration`.
- **Frontmatter**, validated per entry by the zod schema:
  - `title` (string, required). This is the only title source. The body has no `# ` line.
  - `kind`: `case-study` or `agent` (required)
  - `problem`: short buyer-problem label shown on the tile, e.g. "Partner spec review" (required)
  - `summary`: one sentence, used on the index tile and as the item page's meta description (required)
  - `featured`: boolean (default false)
  - `order`: number (required)
- **Body sections**, as `## ` headings with these exact names:
  - case study: `Problem`, `What I did`, `Outcome`
  - agent: `What it does`, `Input`, `Output`, `Before and after`
- **Cross-entry and body checks** run in one shared loader, `src/lib/work.ts`, after `getCollection`. It throws during build when: zero or more than one item has `featured: true`; a body contains a `# ` line; or a required body section for the item's kind is missing or misnamed. Every page reads work items through this loader, so a bad file fails the build instead of rendering a broken page.
- **Ordering** on `/work`: ascending `order`, ties broken by `title`. Grouping by `problem` is deferred until there are at least five items; until then `problem` shows as a small label on each tile.
- **The case study move:** its current `# Case study: Insurance claims API integration` line becomes frontmatter `title`, verbatim, and is removed from the body. It gets `kind: case-study`, `featured: true`, `order: 1`, and `problem` and `summary` written by Marlon. The HTML comment at the top of the file moves below the frontmatter fence, to the top of the body, where `sections()` strips it.
- **Home's Selected work tile** reads the featured item from the loader: h2 is `title`, and the three blocks come from the body's `## ` sections, parsed with the same `sections()` helper `index.astro` uses today. The rendered h2 and block text must be byte-identical to the current home page; this is checked by diffing the built `dist/index.html` Selected work section before and after.

### Section text format
Section bodies in `content/work/`, `content/work-index.md` and `content/studio.md` are plain paragraphs separated by blank lines, the same format the existing `content/` files use and `index.astro` renders today. No markdown lists, links or emphasis inside sections. Steps such as "How an engagement works" are written one per paragraph. The shared loader fails the build if a section line starts with `- `, `* `, a digit plus `. `, or contains `](`. This keeps rendering on the existing helper, adds no markdown renderer, and ships zero client-side JS.

### Item page `/work/[slug]`
- h1 is the frontmatter `title`. `<title>` is `${title} — ${shortName}`, with `shortName` read from `## Name` in `content/positioning.md`, matching the About page's pattern. Meta description is `summary`.
- Each body section renders as an h2 with its paragraphs below, inside one prose tile (`.tile.tile-prose`, as on About).
- A back link "All work" points to `/work`.

### Work index copy: `content/work-index.md`
- `# <h1 text>`: the page h1; `<title>` is `${h1} — ${shortName}`. Required.
- `## Meta description`: at most 155 characters. Required.
- `## Intro`: optional, one or two sentences above the list. Omitted if absent.
If the file or a required part is missing, the build fails.

### Studio page: company profile
`content/studio.md`, written by Marlon, read with the same `sections()` helper. Exact structure:
- `# <h1 text>`: the page h1 and `<title>`.
- `## Meta description`: the meta description, at most 155 characters.
- `## Tile`: one sentence used by the home Studio tile.
- `## What we do`: one sentence of outcome, for whom.
- `## Who it's for`
- `## How an engagement works`: steps from first call to go-live and handover.
- `## Agents`: optional intro paragraph. The list below it is generated from `kind: agent` work items. Each entry shows the item `title` as a link to its item page, with its `summary` below, in the same order as `/work` (ascending `order`, ties by `title`). With zero agent items, this whole section is omitted.
- Contact block, always last: label "Start a conversation", LinkedIn and email links read from `## Links` in `content/positioning.md`, the same source as the home Contact tile.

Any optional `## ` section that is missing is omitted, never shown as placeholder text. `# `, `## Meta description` and `## Tile` are required; if one is missing, the build fails.

### Home Studio tile
- Slot: between Now and Contact, in the right column on desktop (from 52em), in the same stacked order on mobile. Hero, stats, Selected work and Now keep their current positions.
- Label `// studio`. Body is the `## Tile` sentence from `content/studio.md`. One link, text "See the studio", to `/studio`.
- The tile is rendered only when `content/studio.md` exists.

### Launch gating
- **Mechanism for file-presence gating:** a shared helper, `src/lib/studio.ts`, reads `content/studio.md` with `import.meta.glob("../../content/studio.md", { query: "?raw", eager: true })`, which returns an empty object when the file is absent instead of failing the build. The route is `src/pages/[studio].astro` with a `getStaticPaths` that returns `[{ params: { studio: "studio" } }]` when the helper found the file and `[]` otherwise, so no `/studio` page is emitted. `Base.astro` nav and the home Studio tile call the same helper and render nothing when it returns null.
- Deployment is push-to-main, so gating is done by file presence and by branch:
  - **Studio:** if `content/studio.md` does not exist, `/studio`, the Studio nav item and the home Studio tile are not built. Marlon keeps his draft outside `content/` (e.g. `drafts/studio.md`, gitignored) until it is ready.
  - **Work:** all code is built on a feature branch, `feat/work-and-studio`. It merges to main when the case study renders byte-identically on home and at least one agent item has passed the sanitisation check. With only the case study and no agent item, the branch does not merge.
- **When Studio ships:** on 2026-12-07, using whatever the Assignment's conversations have produced by then:
  - Three conversations held: copy uses the founders' own words.
  - One or two held, or booked but not yet held: ship on Marlon's draft, revised with what those conversations said; revise again after each later conversation.
  - None booked: ship on Marlon's draft and revise after the first conversation.
- **Name and price on that date:** if still open on 2026-12-07, Studio ships with the working name "Agent Studio" and no price on the page. Both can change later without code changes.

### Sanitisation check (gate before any work item merges)
This is a manual review by Marlon; no tool automates it. Separately, the project's review-copy command confirms the rendered copy matches `content/`, which catches rendering errors but not sanitisation problems. Checklist for each `content/work/` file:
- No employer name, partner names, internal system or tool names.
- No numbers that cannot be defended outside the employer.
- No screenshots, data samples or field names from employer systems.
- The item still makes sense to a reader who has never seen the employer's tools.
An item that fails any line does not merge.
